# 知识点说明

## mergeVirtualHostAttributes 配置说明

### 概述

`mergeVirtualHostAttributes` 是 uni-app 在微信小程序 (`mp-weixin`) 下的一个编译配置项，用于控制自定义组件虚拟宿主节点属性与组件内部根节点属性的合并行为。

### 配置位置

在 `manifest.json` 的 `mp-weixin` 节点下配置：

```json
"mp-weixin": {
    "appid": "wx7a804c75d979be99",
    "mergeVirtualHostAttributes": true
}
```

### 核心作用

当设为 `true` 时，父组件在使用自定义组件时设置的 `class`、`style` 等属性，会与子组件内部根节点的属性进行**合并**，而不是被隔离忽略。

换句话说，开启后自定义组件表现得像一个"透明节点"，父组件可以穿透组件标签，将属性直接合并到组件实际的根 DOM 上。

### 对比示例

#### 场景设定

自定义组件 `my-card.vue`：

```vue
<template>
  <view class="card-container" style="padding: 20px; background: #fff;">
    <slot />
  </view>
</template>
```

父页面使用：

```vue
<template>
  <my-card class="outter-style" style="margin-top: 30px;">
    <text>这是卡片内容</text>
  </my-card>
</template>
```

#### 不开启（`mergeVirtualHostAttributes: false`）

渲染后的 DOM 结构：

```html
<my-card class="outter-style" style="margin-top: 30px;">
  <!-- ⬆ 虚拟宿主节点，父组件传入的属性停在这里 -->
  <view class="card-container" style="padding: 20px; background: #fff;">
    <!-- ⬆ 组件内部根节点，只有自己的属性 -->
    这是卡片内容
  </view>
</my-card>
```

**结果**：两套属性分别在不同节点上，外部样式无法影响内部。样式被隔离。

#### 开启（`mergeVirtualHostAttributes: true`）

渲染后的 DOM 结构：

```html
<view class="outter-style card-container"
      style="margin-top: 30px; padding: 20px; background: #fff;">
  这是卡片内容
</view>
```

**结果**：

- **class 合并**：`outter-style`（外部）和 `card-container`（内部）合并
- **style 合并**：两边 style 合并到同一个 style 属性
- **宿主节点消失**：不再多嵌套一层

#### 直观对比

```text
不开启:  <my-card style="A">        ← 样式 A 留在宿主节点，透不下去
           <view style="B">         ← 只有 B 生效

开启:    <view style="A; B;">       ← A 和 B 合并，都生效
```

### 实际开发价值

有了这个配置，操作自定义组件就像操作原生 `view` 一样方便：

```vue
<!-- 直接在父组件给自定义组件加间距、定位等样式就能生效 -->
<my-card class="mt20 ml10" style="position: relative; z-index: 10;" />
```

不需要在子组件里通过 `props` 传递样式再手动绑定，开发体验与原生组件一致。

### 技术背景

在小程序中，每个自定义组件都有一个虚拟宿主节点（virtual host node），用于承载父组件传入的属性。默认情况下，这个宿主节点与组件内部的根节点是分离的。微信小程序提供了 `virtualHost` 配置项来控制这一行为，uni-app 通过 `mergeVirtualHostAttributes` 对该能力进行了封装。

## uni_modules 说明

### 简介

`uni_modules` 是 uni-app 的插件目录，相当于 npm 的 `node_modules`，存放从 uni-app 插件市场安装的组件库和插件。**不能删除，也不能加入 `.gitignore`**，需随项目源码一起提交。

## 与 node_modules 的区别

| 对比项 | uni_modules | node_modules |
| --- | --- | --- |
| 来源 | uni-app 插件市场 | npm 仓库 |
| 编译方式 | 源码直接参与 CLI 编译打包 | 作为依赖引用 |
| 管理方式 | 随项目源码提交到 Git | 通过 `package.json` + `npm install` 管理 |
| 安装方式 | HBuilderX 下载 / 手动解压 | `npm install` |

## 使用方式

项目中 `uview-plus` 等已通过 `pages.json` 的 `easycom` 自动注册，**无需手动 import**，直接在模板中使用：

```vue
<template>
  <u-button type="primary">按钮</u-button>
  <u-input placeholder="请输入" />
  <uni-icons type="search" />
</template>
```

### 安装新插件

通过 `easycom` 自动扫描注册的组件（`autoscan: true`），符合命名规范的组件也会自动可用。

#### 方式一：HBuilderX 下载

HBuilderX 打开项目 → 插件市场搜索 → 下载到 `uni_modules/`，再回到 VSCode 继续开发。

#### 方式二：手动下载

前往 [uni-app 插件市场](https://ext.dcloud.net.cn/) 网页端下载 zip 包，解压后放到 `uni_modules/` 下同名文件夹即可。

## status-bar-height（状态栏高度）

`status-bar-height` 是指手机屏幕**顶部的系统状态栏**，即显示时间、电量、信号等系统信息的区域：

```text
┌─────────────────────┐  ▲
│ 12:00   📶 🔋       │  │ status-bar-height（状态栏高度）
├─────────────────────┤  ▼
│   ← 宠你             │  导航栏（navigationBar）
├─────────────────────┤
│                     │
│      页面内容        │
│                     │
└─────────────────────┘
```

### 使用场景

当 `pages.json` 中配置了 `"navigationStyle": "custom"`（自定义导航栏）时，原生导航栏消失，页面会从屏幕最顶部开始布局。需要用 `--status-bar-height` 或 JS 获取状态栏高度来为自定义导航栏留出偏移，防止内容被系统状态栏遮挡。

### 获取方式

```ts
const systemInfo = uni.getSystemInfoSync()
const statusBarHeight = systemInfo.statusBarHeight // 单位：px
```

### 不同设备高度参考

| 设备 | 状态栏高度 |
| ---- | ---------- |
| iPhone 14 Pro | ~54px |
| iPhone 14 | ~47px |
| 大部分安卓 | 24~32px |

## uni.getMenuButtonBoundingClientRect() 封装与适配

`uni.getMenuButtonBoundingClientRect()` 用于获取小程序右上角胶囊按钮（`···` + 圆圈按钮）的位置和尺寸信息，帮助自定义导航栏避开胶囊区域。

### 封装策略：透传 + 归一化

uni-app 不修改返回值，只负责将各平台原生 API 统一调用名称和返回格式：

```text
uni.getMenuButtonBoundingClientRect()
          │
          ├── 微信小程序  → wx.getMenuButtonBoundingClientRect()
          ├── 支付宝小程序 → my.getMenuButtonBoundingClientRect()
          ├── 百度小程序   → swan.getMenuButtonBoundingClientRect()
          ├── 抖音小程序   → tt.getMenuButtonBoundingClientRect()
          ├── QQ小程序     → qq.getMenuButtonBoundingClientRect()
          ├── 小红书       → ks.getMenuButtonBoundingClientRect()
          ├── 鸿蒙元服务   → 原生接口透传
          └── App / H5 / 飞书 → 无封装，返回 undefined
```

### 返回值格式

所有平台返回统一格式（坐标原点为屏幕左上角，单位 px）：

```json
{
  "width": 87,
  "height": 32,
  "top": 48,
  "right": 368,
  "bottom": 80,
  "left": 281
}
```

```text
屏幕宽度 375px
┌────────────────────────────┐ ← top=0
│  12:00       📶 🔋         │   status-bar-height
├────────────────────────────┤ ← top=48（胶囊顶部）
│  📍 南京  [搜索]    ○  ···│ ← height=32，胶囊区域
│                            │   left=281, right=368, width=87
├────────────────────────────┤ ← bottom=80
```

### 平台差异说明

| 平台 | 支持状态 | 特殊说明 |
| ---- | -------- | -------- |
| 微信小程序 | ✅ 支持 | 胶囊固定，尺寸稳定 |
| 百度小程序 | ✅ 支持 | 同上 |
| 抖音小程序 | ✅ 支持 | 同上 |
| QQ小程序 | ✅ 支持 | 同上 |
| 小红书 | ✅ 支持 | 同上 |
| 鸿蒙元服务 | ✅ 支持 | 同上 |
| **支付宝小程序** | ⚠️ 支持但特殊 | 胶囊内按钮可由开发者自定义（如"更多""返回""关闭"的组合），导致 `width` 和 `left` **动态变化**，不能硬编码偏移量 |
| App | ❌ 不支持 | 无胶囊概念，需通过 `plus.navigator.getUIStyle()` 获取异形屏安全区 |
| H5 | ❌ 不支持 | 浏览器环境无胶囊按钮 |
| 飞书小程序 | ❌ 不支持 | 飞书官方未提供该 API |

### 适配方案

```ts
const menuButtonInfo = ref<any>(null)

onLoad(() => {
  // #ifdef MP-WEIXIN || MP-BAIDU || MP-ALIPAY || MP-TOUTIAO || MP-QQ
  menuButtonInfo.value = uni.getMenuButtonBoundingClientRect()
  // #endif
  // #ifdef H5 || APP-PLUS
  menuButtonInfo.value = { top: 20, height: 44 }  // 手动兜底
  // #endif
})

// 导航栏区域高度 = 胶囊顶部 + 胶囊高度 + 底部间距
const headerStyle = computed(() => {
  const info = menuButtonInfo.value
  if (!info) return { height: '88px' }  // 兜底
  return { height: `${info.top + info.height + 20}px` }
})
```

### 关键点总结

| 要点 | 说明 |
| ---- | ---- |
| **封装层次** | 仅统一 API 名称和返回值格式，不自动模拟非小程序端 |
| **不做的事** | H5 / App 端不提供兜底值，开发者需条件编译自行补齐 |
| **支付宝注意** | 胶囊宽度可变，必须动态获取，不能写死 CSS 偏移 |
| **top 值** | 已包含系统状态栏高度，可直接用于定位 |
| **条件编译** | 非小程序端代码不会被编译进去，避免 `is not a function` 错误 |

## uni.getLocation() 使用与说明

`uni.getLocation()` 用于获取当前设备的地理位置信息（经纬度）。

### 授权

调用 `uni.getLocation()` 前，必须先获得用户的位置授权，否则会进入 `fail` 回调。

#### 各平台授权机制

| 平台 | 授权方式 | 说明 |
| ---- | -------- | ---- |
| 微信小程序 | `scope.userLocation` 授权 | 首次调用自动弹授权框，用户同意后才能定位 |
| 支付宝/百度/抖音等小程序 | 平台对应授权机制 | 首次调用弹授权框 |
| H5 | 浏览器 `navigator.permissions` | 由浏览器统一管理，拒绝后需手动改浏览器设置 |
| App | 系统权限申请 | iOS `NSLocationWhenInUseUsageDescription`、Android 运行时权限，uni-app 已封装申请流程 |

#### 微信小程序授权流程

1. **首次调用** — 系统自动弹出授权框，展示配置的用途说明文字
2. **用户同意** — 后续调用不再弹窗，直接返回定位结果
3. **用户拒绝** — 触发 `fail` 回调，且**之后再次调用也不会再弹授权框**，只能引导用户手动开启

#### 拒绝授权的处理方案

```ts
uni.getLocation({
  success: (res) => { /* 定位成功 */ },
  fail: (err) => {
    // 判断是否因拒绝授权导致
    uni.showModal({
      title: '提示',
      content: '定位权限未开启，是否前往设置？',
      success: (res) => {
        if (res.confirm) {
          uni.openSetting()   // 打开设置页，用户可手动开启定位权限
        }
      }
    })
  }
})
```

#### 相关 API

| API | 作用 |
| ---- | ---- |
| `uni.getSetting()` | 查询当前各项授权状态（如 `authSetting['scope.userLocation']`） |
| `uni.authorize()` | 提前发起授权请求（`uni.getLocation` 本身已自动请求，一般不用手动调用） |
| `uni.openSetting()` | 打开设置页，引导用户手动开启被拒绝的权限 |
| `uni.onLocationChange()` | 监听位置实时变化（需先 `uni.startLocationUpdate`） |

#### manifest.json 授权配置

微信小程序的授权弹窗用途说明需在 `manifest.json` 的 `mp-weixin` 节点下配置：

```json
{
  "mp-weixin": {
    "appid": "wx7a804c75d979be99",
    "permission": {
      "scope.userLocation": {
        "desc": "你的位置信息将用于展示附近服务"
      }
    }
  }
}
```

| 配置项 | 说明 |
| ------ | ---- |
| `permission` | 授权配置根节点 |
| `scope.userLocation` | 地理位置权限类型 |
| `desc` | 授权弹窗中展示的用途说明文字，用户在弹窗中可见 |

#### requirePrivateInfos 隐私接口声明

`requirePrivateInfos` 用于声明项目会调用哪些**涉及用户隐私的接口**（微信基础库 2.32.3+ 新增）：

```json
{
  "mp-weixin": {
    "permission": {
      "scope.userLocation": {
        "desc": "你的位置信息将用于展示附近服务"
      }
    },
    "requirePrivateInfos": ["getLocation"]
  }
}
```

**为什么必须配置：**

微信 2023-10-17 起强制执行**隐私保护指引**：

```text
隐私新规前：调用 getLocation 直接弹定位授权框
隐私新规后：
  1. 在微信公众平台填写《用户隐私保护指引》，勾选"位置信息"
  2. 代码中必须声明 requirePrivateInfos: ["getLocation"]
  3. 缺少声明 → 调用 uni.getLocation() 直接失败，
     报错 "getLocation:fail 需要声明隐私接口"
```

**常见取值：**

```json
"requirePrivateInfos": [
  "getLocation",        // 获取位置
  "chooseLocation",     // 选择位置
  "onLocationChange",   // 监听位置变化
  "startLocationUpdate" // 开启位置更新
]
```

**与 permission 的区别：**

| 配置 | 作用 |
| ---- | ---- |
| `permission.scope.userLocation.desc` | 授权弹窗的**用途文案** |
| `requirePrivateInfos` | 声明**用到了哪些隐私接口**（缺了直接调用失败） |
| 公众平台《用户隐私保护指引》 | 后台勾选对应隐私项（微信审核用） |

> 三者缺一不可：后台指引 + `requirePrivateInfos` 声明 + `permission` 文案，微信才会允许小程序调用定位。

### 基本用法

```ts
uni.getLocation({
  type: 'gcj02',        // 坐标系：wgs84(默认) / gcj02
  geocode: true,        // 是否解析地址信息（仅 App 支持）
  success: (res) => {
    console.log(res.latitude, res.longitude)
  },
  fail: (err) => {
    console.log('定位失败', err)
  }
})
```

### 参数说明

| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | :--: | ---- |
| `type` | String | 否 | `wgs84`（默认，GPS 原始坐标）/ `gcj02`（国测局坐标，供 map 组件、`uni.openLocation` 使用） |
| `geocode` | Boolean | 否 | 默认 `false`，是否解析地址，**仅 App 平台支持** |
| `altitude` | Boolean | 否 | 是否返回海拔，开启会减慢定位速度 |
| `isHighAccuracy` | Boolean | 否 | 开启高精度定位（微信 2.9.0+、App/H5 3.4.0+） |
| `highAccuracyExpireTime` | Number | 否 | 高精度定位超时（ms，需 ≥3000） |
| `success` | Function | 是 | 成功回调 |
| `fail` | Function | 否 | 失败回调 |
| `complete` | Function | 否 | 结束回调 |

### type 取值详解

`type` 只有两个取值，决定返回的**坐标系**：

| 取值 | 坐标系 | 说明 | 使用场景 |
| ---- | ------ | ---- | -------- |
| `wgs84` | 世界大地坐标系（GPS 原始坐标） | 苹果地图、谷歌地图等**国外标准**，全球通用 | 纯定位展示、海外地图、GPS 设备数据 |
| `gcj02` | 国测局坐标系（火星坐标） | **国内所有地图**（微信、高德、百度、腾讯）使用的加密坐标，由 wgs84 偏移加密而来 | 国内地图展示、`uni.openLocation`、`map` 组件、逆地理编码 |

**关键区别：**

<!-- markdownlint-disable MD029 -->
1. **同一点两个坐标值不同**（偏差约 50-500 米）

```text
北京市天安门
  wgs84:  39.908823, 116.397470
  gcj02:  39.909637, 116.397951   ← 已加密偏移
```

2. **坐标系混用的后果**

```text
用 gcj02 坐标 → 丢进国外地图(wgs84) → 位置偏移几百米
用 wgs84 坐标 → 丢进国内地图(gcj02) → 位置偏移几百米
```

3. **默认值与推荐** — 不传 `type` 时默认 `wgs84`；**国内项目一律用 `gcj02`**，因为国内地图厂商（高德/腾讯/百度）全部基于 gcj02，微信小程序、`uni.openLocation()`、`map` 组件都必须用 gcj02 才能精确定位
<!-- markdownlint-enable MD029 -->

### 平台差异速查

| 平台 | 定位方式 | geocode | 备注 |
| ---- | -------- | :-----: | ---- |
| 微信小程序 | 微信内置定位 | ❌ 无效 | 需用户授权；地址需逆地理编码 |
| H5 | 浏览器 Geolocation | ❌ 无效 | 需 HTTPS；PC 推荐 Edge |
| App | 高德/腾讯 SDK（需申请 key） | ✅ 有效 | 打包后必须用自己申请的 key |

### 注意事项

| 注意点 | 说明 |
| ------ | ---- |
| **小程序授权** | 首次调用弹出授权框，用户拒绝后触发 `fail`，需引导去设置页开启 |
| **小程序无地址** | 小程序端 `geocode` 参数无效，`res.address` 拿不到，城市名需用逆地理编码接口（高德小程序 SDK、腾讯位置服务等） |
| **合法域名** | 小程序使用第三方逆地理编码接口需在微信公众平台添加 request 合法域名 |
| **腾讯地图变更** | gcj02 免费转换接口已于 2024-07-18 逐步下线，需升级 uni-app 4.24+ 并配置地图厂商 key，否则部分平台定位失败 |
| **H5 HTTPS** | H5 端定位需要 https 服务（localhost 可用 http） |
| **App key 配置** | 真机运行基座用 DCloud 的 key 可定位，云端打包后必须自行申请高德/腾讯 AppKey，且包名、appkey、证书需匹配 |

### H5 端报错记录：map provider not configured or not supported

#### 报错信息（错误实录）

<!-- markdownlint-disable MD033 -->
<font color="red">`getLocation:fail translate coordinate system faild, map provider not configured or not supported`</font>
<!-- markdownlint-enable MD033 -->

#### 复现环境

| 项 | 值 |
| ---- | ---- |
| 平台 | H5 端（浏览器） |
| 代码 | `uni.getLocation({ type: 'gcj02' })` |
| 配置 | `manifest.json` 的 `h5` 节点未配置地图服务商 key |
| 现象 | `success` 不执行，进入 `fail` 回调 |

#### 错误原因

H5 端 `uni.getLocation` 的定位链路：

```text
浏览器 Geolocation API（返回 wgs84 坐标）
        ↓  type: 'gcj02' 时需要转换坐标系
   地图服务商 SDK（高德/腾讯）做 wgs84 → gcj02 转换
        ↓
    返回结果
```

<!-- markdownlint-disable MD033 -->
<font color="red">代码传了 `type: 'gcj02'`，但 `manifest.json` 的 `h5` 节点没有配置地图服务商（高德/腾讯 key），坐标转换没有提供商可用，于是直接失败。</font>
<!-- markdownlint-enable MD033 -->

#### 解决方案

##### 方案 A：配置地图服务商（推荐，坐标准确）

在 `manifest.json` 的 `h5` 节点加 `sdkConfigs.maps`：

**高德地图**（需在[高德开放平台](https://console.amap.com/)申请「Web端(JS API)」key + 安全密钥）：

```json
"h5": {
  "title": "宠物小程序",
  "router": {
    "mode": "hash"
  },
  "sdkConfigs": {
    "maps": {
      "amap": {
        "key": "你的高德Web端JS API key",
        "securityJsCode": "你的高德安全密钥"
      }
    }
  }
}
```

**腾讯地图**（需在[腾讯位置服务](https://lbs.qq.com/)申请 key）：

```json
"sdkConfigs": {
  "maps": {
    "qqmap": {
      "key": "你的腾讯地图key"
    }
  }
}
```

> 配置后需**重启** `npm run dev:h5` 生效。浏览器定位本身还需 HTTPS（本地 `localhost` 开发不受限）。

##### 方案 B：临时改用 `wgs84`（立即可用，但国内坐标有偏移）

```ts
uni.getLocation({
  type: 'wgs84',   // 不转换坐标系，跳过地图服务商
  ...
})
```

但国内地图（高德/腾讯/微信）用的是 `gcj02`，坐标会偏移约 50-500 米，仅适合临时调试，H5 最终上线建议方案 A。

#### 经验教训

| 要点 | 说明 |
| ---- | ---- |
<!-- markdownlint-disable MD033 -->
| <font color="red">**H5 的 gcj02 依赖地图服务商**</font> | 小程序端微信统一申请了 key 无需配置；H5 端要 `gcj02` 必须自己配高德/腾讯 key |
<!-- markdownlint-enable MD033 -->
| **报错关键词定位** | 看到 `map provider not configured` → 优先检查 `manifest.json` 的 `h5.sdkConfigs.maps` |
| **跨端同一段代码** | `type: 'gcj02'` 在小程序/H5/App 三端表现不同，同一份代码要留意各端配置差异 |

## uni.getLocation() 内部原理（uni-app 做了什么）

### 一、编译期：API 映射（透传）

uni-app 编译时会把 `uni.getLocation()` 映射到各平台的原生 API，**不做额外包装，直接透传**：

```text
uni.getLocation()
     │
     ├── 微信小程序 → wx.getLocation()（微信统一向腾讯申请了 key，无需开发者配置）
     ├── 支付宝      → my.getLocation()
     ├── 百度        → swan.getLocation()
     ├── 抖音        → tt.getLocation()
     ├── QQ         → qq.getLocation()
     ├── H5         → 浏览器 Geolocation API + IP 定位兜底
     └── App        → 系统定位 / 三方定位 SDK（由 type 决定）
```

### 二、H5 端：封装了"浏览器定位 + IP 兜底"两段式

uni-app 在 H5 端封装了降级逻辑：

1. 默认调用浏览器原生 `navigator.geolocation.getCurrentPosition()`（GPS / Wi-Fi / 基站）
2. **获取失败时自动降级为 IP 定位** — 调用三方地图 Web 接口（腾讯/谷歌）把客户端 IP 解析成粗略经纬度
3. 平台限制处理：需要 HTTPS、PC 端 Chrome 依赖谷歌服务器（推荐 Edge）

> 这层"定位失败自动降级 IP"的适配是 uni-app 做的，开发者只写一份代码。

### 三、App 端：type 参数决定定位引擎

uni-app 在 App 端根据 `type` 选择底层实现：

| type | 底层引擎 | 实现方式 |
| ---- | -------- | -------- |
| `wgs84` | 系统定位 | Android 原生定位框架（GPS+Network）/ iOS CoreLocation |
| `gcj02` | 三方定位 SDK | 高德/腾讯 SDK 打包进 App，多源融合定位（GPS+基站+Wi-Fi） |

并且：

- **权限处理** — 封装了 iOS/Android 的定位权限申请流程
- **key 匹配校验** — 包名、AppKey、证书签名三者校验
- **geocode 地址解析** — 仅 App 端透传三方 SDK 的逆地理编码能力返回 `res.address`
- 4.31+ 内置腾讯定位；3.3.0+ 优化系统定位免 SDK

### 四、小程序端：最少封装

小程序端 uni-app 基本是**纯透传**，因为小程序原生 `getLocation` 已经封装好权限、坐标系：

- 权限：微信的 `scope.userLocation` 授权机制
- key：微信官方统一向腾讯申请，**开发者无需配置**
- uni-app 只做 `type` 坐标系透传和隐私协议配置提示（2023-10-17 后需声明 `requiredPrivateInfos`）

### 五、统一层：参数归一化

无论哪个平台，uni-app 都会把返回值统一成：

```ts
{ latitude, longitude, speed, accuracy, altitude, verticalAccuracy, horizontalAccuracy, address }
```

开发者不需要关心各平台返回字段差异。

### 六、总结对比

| 平台 | 封装程度 | 底层 | 需三方 key |
| ---- | :------: | ---- | :--------: |
| 微信小程序 | 纯透传 | `wx.getLocation` | ❌ |
| H5 | 封装降级逻辑 | Geolocation + IP 兜底 | ✅（仅 IP 方案） |
| App | 双引擎调度 | 系统定位 / 三方 SDK | ✅ |

> **核心一句话**：小程序端是"裸透传"，H5 端封装了"浏览器定位→IP 定位"的自动降级，App 端封装了"系统定位 / 三方 SDK"双引擎调度和权限、key 校验——各端差异由 uni-app 在内部抹平，对外统一一个 `uni.getLocation()`。
